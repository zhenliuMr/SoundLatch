## SoundLatch v1.2.0 · 首个正式发行版

此前仓库里的 v1.0.0 / v1.1.0 / v2.0.0 三个 tag 含已知缺陷（限幅器漏过峰值、
参数跨线程撕裂、欠载爆音），已全部删除。请直接用本版本。

---

### 修订：勾选「回环捕获」闪退已修（2026-10-20，版本号不变，覆盖发行包）

现象：勾选「回环捕获」后进程闪退，事件日志 `ucrtbase.dll` + `0xc0000005`。

根因：渲染循环的重采样压缩步骤用 `inLen_ - n` 当 `memmove` 长度。断流时取样游标
`cur_` 仍每块递增，很快越过已缓冲帧数 `inLen_`，该减法在 `size_t` 上下溢成 ≈1.8e19，
内存直接踩穿。WASAPI 的回环端点在**没有音频在放**时一个包都不给（不是给静音包），
所以「回环捕获 + 没声音在放」必崩；普通采集始终有静音包，碰不到这条路径。

修复（`src/engine.cpp`，仅此一处逻辑，声音链路一行未改）：

| 位置 | 改动 |
|---|---|
| 压缩步骤 | `n` 先夹到 `inLen_`，`cur_` 兜底回 0 |
| 取样循环后 | `if (cur_ > inLen_) cur_ = inLen_;` —— 饿死时不越过缓冲 |
| 取数前 | `inLen_ + 2 >= capFrames` 时先收缩，防 `want` 下溢 |

验证：修复前 gdb 下点 1–2 次勾选框即 SIGSEGV；修复后连续勾选/取消 6 次稳定，
事件日志无新增 APPCRASH；`dsp_test` 12/12、`overshoot_test` 6/6、`engine_glitch_test` 全过。

> 回环捕获在没有声音在放时电平柱一直是 0、延迟显示 0，这是 WASAPI 的正常行为，
> 不是没启动 —— 放一段音频就会动。

### 判据重写：用相对判据替换两个无效参数

原面板上的「环境阈值」和「瞬态灵敏度」被移除，改由内置判据接管。
在 189 条三维分层样本（覆盖素材库全部 62 个非空频谱形态格，无缺口）上实测，
原设计无法工作：

| 参数 | 实测结论 |
|---|---|
| 环境阈值（绝对 dBFS） | 脚步带被压 **-25 dB**，反而比低频环境的 **-11.5 dB** 更狠 —— 方向是反的。且随系统音量、玩家距离漂移，没有稳定取值 |
| 瞬态灵敏度（移动门限） | 各层瞬态陡度 P90 都在 +5 dB 左右，单靠"陡"分不开；bias 0→6 选择性单调下降 1.31→0.90 |

新判据（两者都与绝对电平无关）：

- **谱倾斜抑制** — 实测低频环境 tilt **+16.6 dB**，脚步带仅 **+2.1 dB**，分离度 14 dB
- **瞬态频段分布** — 要求「中频够陡」且「中频比低频更陡」；脚步主体在 600–3 kHz，爆炸冲击在 <600 Hz

滑杆从 4 个减为 3 个：环境抑制 / 脚步增强 / 最大输出。

### 修复的缺陷

| 缺陷 | 现象 | 修复 |
|---|---|---|
| 限幅器块边界漏过峰值 | 输出超出上限 0.006–0.074 dB | 输出端加硬钳位（砖墙限幅的定义就是永不超过） |
| 参数跨线程撕裂 | UI 线程改参数、音频线程读到"一半新一半旧"，撕裂率 1–2% | 参数量化打包进单个 `uint64`，一次原子读天然一致 |
| 重采样欠载爆音 | 断流后重复陈旧样本，恢复瞬间 0.79（-2 dBFS）相位跳变 | 改 5 ms 淡出/淡入 |
| 「最大输出」范围太窄 | 5% 与 100% 的 RMS 差不足 0.3 dB，听不出区别 | 范围从 -18…0 扩到 **-36…0 dB**，5%↔100% 差 30 dB |
| 削顶检测误报 | 「最大输出」设 100% 时正常信号被记为削顶 | 改为按用户设定上限判定 |
| 勾选「回环捕获」进程闪退 | 无音频在放时 0xC0000005（`ucrtbase!memmove`） | 夹住游标与长度，见上方修订段 |

### 移除 APO 驱动方案

Win11 第三方 APO 必须走微软驱动包扩展 INF + 官方签名，无法自签挂载。
相关代码与安装包已删除，`docs/02`、`docs/03` 加了废弃标记。

### 使用要求

- **Windows 10 / 11**，x64
- 首次运行需安装 [VB-Cable](https://vb-audio.com/Cable/)（仓库内 `dist/vbcable/` 自带）
- **VB-Cable 的 Internal Sample Rate 必须设为 48000**（本机出厂是 96000，与 48 kHz 端点不匹配会逼引擎做 ±4% 重采样，产生偶发咔哒）

### 延迟

| 环境 | 端到端延迟 |
|---|---|
| 本机（Realtek，驱动固定 22 ms 缓冲） | 约 44 ms |
| 典型消费级主板/耳机（10 ms 缓冲） | 约 25–30 ms |

算法自身只占 **0.67 ms**（一个控制块的前视）。
