## 这一版解决什么

> "把最大输出调低以后，一发枪声过去，接下来两三秒整个战场都变小声，脚步也跟着没了。"

原因在限幅器：它是**整条混音一个增益**。枪声尾音持续高于你设的上限时，它就把包括脚步在内的一切一起压下去。
实测一发 3.2 秒的长尾枪声会让整段混音全程处于压缩态，脚步带跟着掉 **3–14 dB**（上限设得越低掉得越多）。

v1.3.0 换了做法：**不再整条压，只削两端**。

### 你会听到的变化

| | v1.2.0 | v1.3.0 |
|---|---|---|
| 枪声 | 被整条压成"闷响"，尾音拖着一片安静 | 只削掉 **<150 Hz 的轰头**与 **>3 kHz 的炸耳**，中频保持原样 |
| 脚步 | 枪声期间跟着整体掉 3–14 dB | **150 Hz–3 kHz 完全不动**，不跟着沉 |
| 混音整体 | 枪声结束后还要被压低 0.5–3 秒 | 压缩窗口缩短一半左右 |
| 枪声音色 | — | **会比以前薄一点**，这是有意的：薄掉的正是炸耳的那部分 |

实测（真实素材、同一信号，改前 → 改后）：

- 短促枪声的压缩窗口：**160 ms → 90 ms**（上限 −6 dBFS）、**210 ms → 130 ms**（−12 dBFS）
- 长尾枪声最大压缩量：**−4.6 dB → −4.3 dB**
- 枪声 4–16 kHz 与 40–300 Hz 能量比：**0 dB → −2.0 dB**（炸耳感下降）
- 脚步声在枪声窗口内的电平变化：**−4.5 dB → −3.9 dB**

## 也修掉了一个闪退

**勾选「回环捕获」会直接崩溃**（没有报错窗口，进程消失）。

原因：WASAPI 的回环捕获在**没有任何声音在播放时一个数据包都不给**（不是给静音包）。没有数据进来，
引擎的取样游标就越跑越靠前，几百毫秒后一次缓冲区搬移算出天量长度，进程在系统 C 运行时里当场崩掉
（事件日志：`ucrtbase.dll` / `0xc0000005`）。

普通采集（CABLE Output）即使没声音也会持续给静音包，所以以前没暴露；只有回环捕获 + 没声音在放才会撞上。

已修复：游标被夹在已缓冲数据范围内，断流多久都不会越界，数据恢复后立刻续上。
验证：修复后调试器下无法复现，发行版连续勾选/取消 6 次稳定，原有的 12 项离线验收与 6 组限幅溢出全过。

> 顺带说明：回环捕获在没声音时电平柱本来就是 0、延迟也是 0 —— 这是系统的正常行为，不是没启动。

## 一定要看：上限不是音量旋钮

「最大输出」是**绝对天花板**，不是衰减量。上限越低，枪声尾音高于天花板的时间越长、被限幅压住的时间也越长，
整段混音都会跟着变小 —— 这就是旧版"整局变小声"的根源。

- **建议 −3 ~ −6 dBFS（滑杆 60–80 %）**
- **不要低于 −12 dBFS**

如果你以前为了"枪声不炸耳"把它拉到 20 %，这一版可以往回调了：炸耳的部分已经由自动处理接管。

## 已知问题（本版未修改）

- **首次启动只驻留托盘，不会自动弹面板。** Win10/11 默认把新托盘图标收进「显示隐藏的图标」，
  看起来像没启动。**再点一次 exe**，面板就会出现在右下角；或从托盘溢出区把图标拖到任务栏。
- exe 未签名，首次运行可能出现 SmartScreen 提示（更多信息 → 仍要运行）。
- 打不开时请先看任务管理器里有没有 `SoundLatch.exe`，再看电脑管家/Defender 是否拦截。

## 使用要求

- **Windows 10 / 11，x64**
- 依赖 [VB-Cable](https://vb-audio.com/Cable/)（仓库 `dist/vbcable/` 自带）
- **VB-Cable 的 Internal Sample Rate 必须设 48000**，否则引擎要做 ±4 % 重采样，会有偶发咔哒

单文件绿色版，解压即用，无安装、无运行库依赖。配置在 `%APPDATA%\SoundLatch\config.ini`。
